# tools

Small editing and release helpers for the MDP workspace (the three repos checked out side by side under `MDP/`). They are
not part of any image: no Dockerfile copies this folder. Run them from the `MDP/` folder.

| Tool | Use |
|---|---|
| `multi_replace.py` | Exact-text edits across files, all-or-nothing, CRLF and BOM kept, control characters refused. A file named in several `@@@ file` blocks (or spelled two ways) has its edits merged in the order written, with a note. `python local-deploy/tools/multi_replace.py - <<'EOF'` with `@@@ file PATH` / `@@@ old` / `@@@ new` blocks; `--dry-run` previews. A spec that is long or full of quotes goes in a file (`multi_replace.py PATH`, written with the Write tool) instead of a heredoc. `@@@ cut` / `@@@ until` deletes everything from one text up to another without retyping it. |
| `json_patch.mjs` | Structural JSON edits by path (`set`, `add`, `replace`, `remove`, `merge`, `test`; RFC 6901 pointers), same all-or-nothing and format-keeping guarantees. Refuses a file whose layout `JSON.stringify` would not reproduce, so use `multi_replace.py` for hand-formatted JSON. |
| `mdp_status.sh` | Read-only snapshot of every repo under `MDP/` in about 30 lines: branch, +ahead/-behind `origin/main`, dirty files, the PR for the branch, and one verdict per other local branch (in origin/main, with a note when the local main is behind and `git branch -d` would refuse it / merged with tip == PR head, so deletable / merged with commits beyond the PR / open / no PR). Never deletes or checks anything out; deletable branches are printed as a command to copy. `bash local-deploy/tools/mdp_status.sh [REPO...] [--no-fetch] [--no-gh] [--files N]`. |
| `token_audit.mjs` | Read-only, measured audit of where tool-output tokens go: from the session transcripts, result size by category (git, tests, lint, file reads, edit scripts, ...), redundant CLAUDE.md reads and the largest results; per repo the commit, `fix` and revert counts and most-touched file; the retro log's near-miss and REPEAT counts. `--check-log` lists retro `FIXED` items whose friction was logged again later. `--since/--until WHEN` window it; `--record` appends a row to `.claude/retro/metrics.tsv` (the only thing it writes) and prints the change against the previous row. `node local-deploy/tools/token_audit.mjs [--since WHEN] [--until WHEN] [--check-log] [--record --label NAME]`. **`--commands`** prints instead how often each shell command ran (by program and subcommand: `git -C * log`, `gh pr view`; heredoc bodies, quoted text and `2>&1` are not commands) sorted into auto-allowed (hidden), SUGGEST (read-only, with the `Bash(... *)` pattern), JUDGE (project and package scripts), WRITES and RUNS CODE, minus what `.claude/settings.json` and `settings.local.json` already allow, plus MCP tools that read by name; `--min N`, `--top N`, `--all-projects`, `--sample KEY` (what a key was made of). It prints and edits nothing: run it before `/fewer-permission-prompts` instead of mining transcripts by hand. `git -C ...` is treated as needing its own rule (the existing rules say it prompts). |
| `open_pr.sh` | Push the current branch and open its PR, the half before `finish_pr.sh`. **Dry run by default** (prints the plan: branch, commits, title, what would be pushed; pushes nothing); `--yes` does it. Refuses on the base branch, with no new commits, or when an open PR already exists; never forces a push; adds the attribution line to the body. You still write the commit, title and body. `bash local-deploy/tools/open_pr.sh REPO --title "type(scope): text" --body-file FILE\|- [--base main] [--draft] [--yes]`. |
| `run_tests.sh` | Run every `test_*.sh`, `test_*.mjs` and `test_*.py` in this folder in parallel (discovered, so a new test file is included automatically) and print one line per suite with its count and time; a failing suite adds the tail of its output. About 90 s for all of them on Windows instead of about 220 s one after another. `bash local-deploy/tools/run_tests.sh [NAME...] [--jobs N] [--list]`. |
| `guard_bash.mjs` | A Claude Code PreToolUse hook for the Bash tool that refuses commands known to hang the shell, or to be quietly rewritten by it, before they run: a heredoc with an empty body (an empty program to `python3 -` made Python start its interactive prompt and loop, 20 MB of output; it happened three times), a heredoc that is never closed, and a bare `python` / `python3` / `py` / `node` or `python -` with nothing feeding it. Heredoc bodies are never scanned, `node -v` and `--version` are fine, and `# guard_bash: allow` in a command opts a deliberate repro out. Installed in `.claude/settings.json` (not tracked): `"hooks": {"PreToolUse": [{"matcher": "Bash", "hooks": [{"type": "command", "command": "node \"$CLAUDE_PROJECT_DIR/local-deploy/tools/guard_bash.mjs\"", "timeout": 10}]}]}`. Replayed over 2,010 historical commands it flagged 4, all real. It also blocks a doubled backslash in a python or node script (since 2026-10-05; it was advice before), because the Bash tool delivers a typed pair as one backslash (a doubled backslash before `n` in a python string writes a real newline): the block message gives the fix (write the script with the Write tool, or build the backslash with `chr(92)` / `String.fromCharCode(92)`), and `# guard_bash: allow` runs a deliberate one. It fires on about 1.6% of historical commands. **Wrong working directory** (since 2026-10-05): the hook input carries the shell's `cwd`, and the Bash tool keeps the directory of an earlier `cd`, so `node degree-specs/build.mjs` or `sed src/lib/x.js` failed with "cannot find" at least six times (retro 2026-10-02, 10-03, 10-05). The hook blocks a relative path (a word with a slash) that does not exist in the `cwd` but does exist under the workspace root or one repo folder, and says where; it names the folder to `cd` into. Left alone: a command that does its own `cd`, `git -C`, `--prefix` or `--cwd`, a path that exists nowhere (a file the command is about to create), the target of `>`, quoted text with a space in it, bare words such as `src` or `docs`, absolute and `~` and `$VAR` paths, flags and URLs. Replayed over 3,128 historical commands it flagged 4, all from a stale `local-deploy` copy that has since been deleted (a first version with bare words flagged 46, all false). The transcripts record the session's directory rather than the shell's, so its recall cannot be replayed; the live hook was checked instead. `GUARD_BASH_ROOT` overrides the workspace root (the tests). |
| `regen.sh` | Run the generated-data chain in order: Prototype `build_courses.mjs` -> `degree-specs/build.mjs` -> Frontend `npm run build:catalog` (about 3 s), then report each of the five generated files as changed or unchanged (byte comparison, line endings ignored: `git status` shows these as modified under `core.autocrlf` when they are not), the diffstat per repo and what to commit where, Prototype first. A failing step stops the chain and shows its output. `--check` runs it, puts every file back and exits 1 if a committed generated file is stale. Never commits or switches branch; the network scrape is not part of it. `bash local-deploy/tools/regen.sh [--check]`. |
| `start_branch.sh` | Start a work branch in one step, the half before `open_pr.sh`: fetch, check out the base, fast-forward it to origin, create the branch from it. Refuses (changing nothing) on uncommitted tracked changes, a branch name that already exists locally or on origin, an invalid name, or a local base with commits origin lacks; notes, and goes ahead, when it leaves a branch whose commits are not pushed. Never deletes, resets or forces. `bash local-deploy/tools/start_branch.sh REPO type/short-name [--base main]`. The PR flow is now three lines: `start_branch.sh`, commit, `open_pr.sh REPO --title ... --body-file - --yes <<'EOF'` (the body on stdin, so no temp file), then `finish_pr.sh`. |
| `finish_pr.sh` | Wait for CI, merge a PR, fast-forward local `main`, delete the PR's local branch only if its tip is the merged head. `bash local-deploy/tools/finish_pr.sh REPO PR [--method ...] [--wait N] [--delete-remote] [--dry-run]`. |
| `release_status.sh` | Where a Release run stands, in one call, after `gh workflow run release.yml`: the run, its Assemble, Publish, Verify and Notify steps, and the latest GitHub release. Exit 0 once Publish and Verify succeeded (the run's cleanup steps keep going a minute longer and are not worth waiting for), 1 on a failure, 2 when not finished. `--wait` polls (run it in the background: a release takes 4 to 5 minutes). `bash local-deploy/tools/release_status.sh [RUN_ID] [--wait] [--timeout SECONDS]`. |

Release preflight is separate: `release-tools/preflight.sh` (see the README's "Shipping a release").

Tests (CI runs the same command): `bash local-deploy/tools/run_tests.sh` runs every suite in this folder in parallel and prints
one line each; pass a name (`run_tests.sh finish_pr`) to run one. Each suite can still be run on its own (`test_*.sh`
with bash, `test_*.mjs` with `node --test`, `test_*.py` with `python -m unittest`).
